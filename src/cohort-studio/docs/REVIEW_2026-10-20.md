## Verified

**V1. Deployment: `APP_SHA` build arg is never supplied (medium)**
- `Dockerfile:21-22` (`ARG APP_SHA=unknown`); `docker-compose.yaml:4-5` (`build: context: .`, no `args`); `.devcontainer.json:22-25` runs `self_update.sh` on every start.
- Evidence: no caller of the compose build passes `APP_SHA` (nothing in repo does), so every image ships `unknown`. Consequence: `/api/version` reports `unknown`, the post-start self-update can never no-op (full tarball fetch + `npm ci` + build on every devcontainer start), and `tests/cohort-studio.sh:31-41` `EXPECTED_APP_SHA` cannot pass without a caller-supplied value. A VM that cannot reach GitHub keeps old code forever.
- Fix: add `args: { APP_SHA: "${APP_SHA:-unknown}" }` to the compose build (or fall back to fetching the branch head in Dockerfile when the arg is unset).

**V2. Self-update never removes deleted modules (low)**
- `self_update.sh:91` `cp -a "${tmp}/app/." "${APP_ROOT}/"` — overlay copy. Upstream module renames/deletions leave stale top-level modules in `/app`; staged-dir validation (`self_update.sh:87-88`) can't catch a stale/-new overlap in the live root. Also stages dev-only `tests/` + fixtures into the live app dir (bloat).
- Fix: `rsync -a --delete "${tmp}/app/" "${APP_ROOT}/"` after validation.

**V3. `VersionFooter` can reload mid-update (low, UX)**
- `App.tsx:46-53`: `before = sha` — if the user clicks Update before `api.version()` resolved, `before === ""`, and the first 5 s poll passes `v.sha !== ""`, reloading while the update is still running; the button then reports false success until the restart lands.
- Fix: capture `before` with a fresh `api.version()` at click time, or reload only when `before` is non-empty.
